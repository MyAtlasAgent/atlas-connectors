# Grok Bot desktop: separate route

Grok Bot desktop and the SuperGrok CLI are distinct execution surfaces. A product
name does not prove the served model, provider family, login, account pool or
review independence. No desktop app binary or vendor implementation is included.

An Atlas-owned automatic desktop connector was not located in the inspected
pinned Atlas sources and operator tools. The existing documented route is manual
delivery; this section includes that contract without presenting it as an SDK.

## Manual handoff

1. Prepare a scoped packet with mission ID, exact candidate SHA, requested work,
   withheld actions, expected return and declared custody.
2. Deliver the packet into the intended desktop conversation yourself. Record
   delivery separately from an explicit acknowledgement by the receiver.
3. Obtain the returned findings and the actual execution surface/model evidence.
   Missing identity evidence stays UNKNOWN.
4. Give the return to the Atlas owner for validation and reconciliation. The
   desktop conversation does not update canonical lifecycle or accept its own
   work merely by emitting a return.

`examples/packet.md` is synthetic reading material, not permission to perform real
repository or account actions. No automatic delivery or unsolicited inbound push
is claimed. An automated desktop bridge would require its own implementation,
provenance and qualification; it cannot inherit CLI qualification by its name.
